# D1/D2 拓扑审计与动态图结论边界

## 审计对象与规则

审计工具 `tools/reacr_rca_topology_audit.py` 读取模型实际使用的：

- `samples/train_samples.pkl`
- `samples/test_samples.pkl`

每个图快照的有向边以端点多重集统计，平行边会保留。审计过程：

- 不使用 `graphs_info/call_edges.pkl` 补全边；
- 不添加自环；
- 不推断未记录的调用关系；
- 独立报告训练集、测试集及按时间排序后的合并序列；
- 检查 DGL `edata` 中是否存在边属性和名称类似 `w`/`weight` 的边权。

因此，下表只描述序列化快照中真实保存、且会被当前模型读取的拓扑。

管线写入 `topology_audit.json` 的解释字段也由上述审计值数据驱动生成：`fixed_edge_topology_in_both_splits` 只有在训练、测试两部分都固定时才为真，`observed_edge_changes_in_any_split` 与之相反。代码不再无条件宣称数据支持固定拓扑。

## 正确解释

### D1

D1 不是完全固定拓扑：7,200 个快照中存在 8 种边集和 15 次相邻切换。审计确认每个快照均有 46 个节点，但节点语义一致性仍依赖数据生成阶段沿用同一编号映射；序列化部署拓扑图中的有向边集合则有少量真实变化，而不是实验代码合成的变化。因此，D1 可以用于检验显式边增删动态是否为根因排序提供额外信息。

审计本身只能证明序列化边集发生变化。将这些变化归因为部署拓扑变化仍需 Kubernetes 事件、部署版本、实例生命周期或原始 trace 等额外证据；论文中应使用“观测到的边集变化”，除非已经完成外部验证。

### D2

D2 的 14,400 个快照节点数均为 18，并具有同一个 66 条有向边的端点多重集。D2 的节点观测特征可以随时间变化，但显式拓扑动态特征中的入/出度差分和边增删通道恒为零；节点语义一致性同样依赖数据生成阶段沿用同一编号映射。

因此，D2：

- 可以验证模型在固定拓扑上的退化兼容性；
- 可以检验时变节点属性和异常演化建模；
- **不能**验证拓扑演化建模的有效性；
- 不能通过随机删边、目录补边或合成切换来替代真实动态图证据，除非将其明确设计并报告为独立的合成实验。

## 模型窗口中的变化密度

快照级的 15 次切换不等于每个模型窗口都有动态拓扑。按当前窗口构造和实际图边统计：

| 数据集/窗口集合 | 窗口数 | 含拓扑变化 | 比例 | 说明 |
| --- | ---: | ---: | ---: | --- |
| D1 全部 case 窗口 | 210 | 6 | 2.86% | 6 个窗口内共观察到 12 次相邻切换。 |
| D1 正式 runner 训练 case | 84 | 3 | 3.57% | `time_strict` 且 `feedback_sample_ratio=0.4`。 |
| D1 正式 runner 验证 case | 21 | 0 | 0% | 该划分不能单独评估变化窗口。 |
| D1 正式 runner 测试 case | 105 | 3 | 2.86% | changed/stable 指标必须连同样本数报告。 |
| D1 正常训练滑窗 | 3,705 | 27 | 0.73% | 27 个重叠窗口只源于训练序列的 3 次底层切换，不是 27 个独立事件。 |
| D2 case/正常窗口 | — | 0 | 0% | 所有窗口均固定拓扑。 |

上述 84/21/105 是 `tools/reacr_rca_final_study_runner.py` 默认 `--feedback_sample_ratio 0.4` 的正式实验协议，不是所有管线调用的通用划分；直接运行管线且沿用 D1 配置中的 0.3 时会得到 63/42/105。因此，“D1 支持动态图实验”与“D1 的动态监督充分”是两件不同的事。当前数据只提供稀疏变化证据；总体 A@K 可能主要由稳定窗口决定，不能独立支撑强泛化结论。

### 边权

D1 和 D2 的所有被审计快照均没有 `edata`，因而不存在数据集提供的调用频率、延迟或强度边权。当前实验应报告为无权有向图。若未来从原始 trace 构造边权，必须记录构造窗口、聚合规则、缺失值处理和数据泄漏检查，并作为新的数据处理版本重跑。

## 模型如何使用实际拓扑

每个节点在窗口每一步提取 8 个结构通道：

1. 当前入度；
2. 当前出度；
3. 相对上一快照的入度变化；
4. 相对上一快照的出度变化；
5. 新增入边数；
6. 移除入边数；
7. 新增出边数；
8. 移除出边数。

第一步没有前序快照，因此六个变化通道为零。固定拓扑下，所有后续变化通道也为零。静态度通道和动态变化通道分别投影后与空间状态融合。

关系头首先构造时间级支持 `lag_alignment_topology_mask[B,L,W,target,source]`。对每个时滞 `l` 和目标时刻 `t≥l`，只有源—目标边真实存在于目标快照 `t` 时，异常乘积 `source(t-l)×target(t)` 才会计入该节点对的时滞 affinity；分母也是实际有效时刻数，而不是整个窗口长度。不存在任何有效目标时刻的 affinity 明确为零。

模型同时保留两个聚合视图：`lag_topology_mask[B,L,target,source]` 是时间级支持沿 `W` 的并集，用于约束该节点对哪些时滞可以参与 softmax；`topology_mask[B,target,source]` 再沿 `L` 取并集，用于最终关系 logits。此前文档只描述 4D 时滞并集，会让人误以为 affinity 仍对所有时间点平均；当前实际计算已经在 5D 时间级掩码处完成筛选。模型还保留“空源”概率，避免强迫每个响应节点都选择一个图内源。该对齐规则是可审计的建模约束，不是时间因果识别保证。

关系头趋势/季节分解的移动平均 `kernel_size` 必须是正奇整数；偶数、非正或非整数输入在构造阶段直接报错。该约束保证前后对称填充后仍与原窗口长度严格对齐，并已有回归测试覆盖。

排序器的图先验也不再只读取窗口末帧。它对每个时刻使用该时刻的观测图和节点异常信号分别计算入邻居/出邻居证据，再沿完整窗口聚合；`freeze_first` 只冻结图，逐时刻异常信号仍保持原样，从而让固定拓扑对照只移除边演化信息。

事件链导出不再为整条路径共用一个全局时滞。每条路径边都从该节点对的时滞分布中导出 argmax 时滞、期望时滞和置信度，并将预测时滞与节点异常起始时间差比较，报告一致率与平均绝对误差。若模型关系边在观测图方向中没有对应项，主标签为 `model_relation_only`；历史 `causal_inferred` 仅为弃用兼容别名。数据没有真实传播链/边时滞标签，因此这些量只能作为内部一致性证据。

## 必须报告的消融

使用相同时间划分、seed、训练轮数和超参数，至少比较：

| runner 名称 | 设置 | 目的 |
| --- | --- | --- |
| 主模型 | `--graph_sequence_mode observed --enable_topology_dynamics --topology_feature_mode full` | 使用观测图序列、静态度和动态边变化。 |
| `no_topology_change_features` | `--graph_sequence_mode observed --topology_feature_mode static_only` | 去除六个显式变化通道，只保留度信息。 |
| `topology_dynamic_features_only` | `--graph_sequence_mode observed --topology_feature_mode dynamic_only` | 只保留显式动态通道。 |
| `frozen_window_topology` | `--graph_sequence_mode freeze_first` | 同一窗口每一步都使用窗口首个真实图，统一冻结所有消费图序列的分支。 |
| `no_explicit_topology_encoder` | `--disable_topology_dynamics` | 去除显式拓扑编码器，但不去除空间图、关系图约束和图先验。 |
| `no_relation_topology_constraint` | `--relation_topology_mode none` | 去除关系候选的图支持约束。 |
| `no_topology_change_oversampling` | `--normal_topology_change_oversample_factor 1` | 去除正常训练变化窗口的加权采样。 |

必须特别区分 `static_only` 与固定拓扑。`static_only` 只关闭显式动态特征；空间消息传递、关系掩码和排序图先验仍读取每一步的观测图，所以它不是冻结图对照。`frozen_window_topology` 才把每个窗口内的图序列统一冻结为首个真实快照，并且不制造新边。D1 的动态图证据至少应联合比较主模型、`no_topology_change_features` 和 `frozen_window_topology`。在 D2 上，动态通道恒为零且图序列本身固定，这些比较不能构成拓扑演化有效性的证据。

## 稀疏变化的训练与评测处理

正常训练窗口的默认变化过采样因子为 4。原始变化窗口占比为 `27/3705=0.729%`；加权采样中的期望概率质量为 `108/(3678+108)=2.853%`。该策略只是提高训练时见到变化窗口的频率：

- 不复制或修改原始图；
- 不改变 case 训练/验证/测试划分；
- 不用于测试集；
- 不能把 27 个重叠窗口解释为 27 次独立变化。

主模型和基线评测都按 `window_has_topology_change` 导出 `topology_strata.changed` 与 `topology_strata.stable` 的样本数和 A@K。正式 runner 已把这些字段收集到逐运行 CSV、多 seed 聚合表和最终 Markdown 报告，而不是只留在单次 JSON。在正式 runner 的 0.4 协议下，D1 验证集没有变化窗口，因而模型选择指标不能声称验证了动态窗口泛化。

## 实现级梯度检查

在 D1 测试序列索引 `229:239` 的真实动态窗口中，边数轨迹包含 `268→256→268`，8 维提取器产生 56 个非零动态特征。一次前向/反向检查中，动态投影参数的梯度范数为 `0.0004352666`，拓扑融合初始缩放为 `0.1`，时滞拓扑掩码/权重也存在非零项。这证明动态通道处在实际计算图和损失反向路径上；它不证明动态通道提高了 A@K，也不替代多 seed 消融。

当前 61/61 项单元测试以及 D1/D2 真实数据小规模端到端运行已通过，其中包含时间级 lag 支持、正奇整数移动平均核及非整数拒绝、早期图快照影响图先验、DeepHunt 近并列梯度、外部 `base_dir` 和拓扑分层汇总报告的针对性测试。D1 最多 16 个 case 的 smoke 中，all-case/train-case 各包含 1 个变化窗口，导出的 5D mask 为 `[8,3,10,46,46]`，动态投影梯度范数为 `1.990379096e-4`，并成功写入 NPZ；D2 对应 mask 为 `[4,3,10,18,18]`、动态梯度为 0，符合固定拓扑预期，真实 E2E 也验证了新的候选字段。训练、评估、解释和导出均退出码 0。这是实现路径验证，不是完整五 seed 结果，也不能用于宣称动态图建模提升了性能。

## 复现命令

```bash
python -m tools.reacr_rca_topology_audit \
  --dataset D1 \
  --sample-dir data/D1/samples \
  --output res/topology_audit_D1.json

python -m tools.reacr_rca_topology_audit \
  --dataset D2 \
  --sample-dir data/D2/samples \
  --output res/topology_audit_D2.json
```

若需要逐一检查所有边集，可增加 `--include-edge-sets`；该选项会显著增大 JSON 文件。
